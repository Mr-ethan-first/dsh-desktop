# DeepSeekAgent 智能体能力评估报告 · 与 WorkBuddy 竞品比对

> 评估日期：2026-09-01
> 评估对象：`deepseek-harness-master` 的 Electron `DeepSeekAgent` 客户端 + `electron/harness` 运行时
> 评估目标：全面摸底当前智能体能力边界，与 WorkBuddy 做竞品比对，为后续增强提供路线依据
> 范围说明：**在线任务（依赖外部在线 API 的联网搜索 / 云端服务调用）不在本次评估重点**；**交互友好型（UI/UX）为重点关注**；核心 agent 能力（工具 / 插件 / 会话 / 工作空间 / 记忆 / 技能 / 稳定性等）一并关注。

---

## 1. 评估方法

- **代码实证**：对 `apps/agent-client`（前端 React + Electron 外壳）与 `electron/harness`（运行时：session / agent-loop / llm / mcp / skill / tools / plugin-host）做静态探查，确认哪些能力已真正落地、哪些仍是占位。
- **竞品对照**：以 WorkBuddy 的公开能力架构（多专家、插件市场、自动化、浏览器自动化、多模态生成、文档处理、可视化、三层记忆、技能系统、任务管理）逐项比对。
- **重点维度**：交互友好型（用户输入/反馈/导航/状态可见性）单列专项；其他功能维度做成熟度分级（✅ 已落地 / 🟡 部分落地 / ❌ 缺失）。

## 5. 交互友好型专项分析（用户重点关注）

### 5.1 当前交互优势

- **会话层级直观**：空间 → 目录 → 任务三级树，符合「按项目组织对话」心智模型。
- **新建对话零摩擦**：WorkBuddy 风格 composer，底部直接选工作空间 + 配权限，首句即标题，无需弹窗。
- **成本透明**：顶栏 Token chip 可展开，看得到每个模型消耗多少、输入输出各多少。
- **文件上下文强**：预览面板 + 定位按钮直接跳到预览文件目录（已修复为 `showItemInFolder`）。
- **目录操作可达**：左侧栏文件夹三点菜单直达资源管理器 / 文件管理。

### 5.2 交互差距（对比 WorkBuddy）

| 交互能力 | 当前状态 | WorkBuddy | 差距说明 |
|---------|---------|-----------|---------|
| 命令面板 / 斜杠命令 | ❌ 无 | ✅ `/` 触发技能 | 高级用户效率瓶颈 |
| 快捷键体系 | ❌ 无文档化快捷键 | ✅ 隐式 | 重度用户切换成本高 |
| 实时反馈 / Toast 中心 | 🟡 仅有图片模型提示 toast | ✅ 统一通知 | 长任务状态可见性弱 |
| 主题切换 | ❌ 无（固定深色） | ✅ IDE 主题跟随 | 弱个性化 |
| 多窗口 / 分屏 | ❌ 单窗口 | 🟡 面板内 | 多任务并行受限 |
| 富附件交互 | 🟡 拖拽/粘贴图片 | ✅ 多类型 | 文件批处理弱 |
| 设置聚合 | 🟡 分散 8 个屏 | ✅ 集中设置 | 新用户上手成本高 |
| 错误可解释性 | 🟡 部分 | ✅ 结构化提示 | 模型挂起/超时反馈模糊 |

### 5.3 交互增强建议（P0/P1）

- **P0**：引入命令面板（Ctrl/Cmd+K），聚合「新建会话 / 切换模型 / 打开设置 / 运行技能」等高频动作。
- **P0**：统一 Toast / 通知中心，把「图片模型提示 / 创建失败 / 工作空间锁定」等状态收敛为一处。
- **P1**：快捷键体系（新建会话、发送、切换会话、定位文件）。
- **P1**：长任务进度条 + 可取消（AbortController 已具备，缺 UI 暴露）。
- **P1**：设置聚合为一屏 + 搜索；降低 8 屏分散带来的认知负担。

## 6. 其他功能维度分析

### 6.1 核心能力成熟度

- **已对齐 WorkBuddy 的**：会话树、工作空间、多模型、视觉输入、fs 工具、MCP、技能注入、稳定性。
- **需补齐的护城河能力**：插件市场（让第三方能力即插即用）、自动化引擎（后台定时跑 agent）、浏览器自动化（网页信息闭环）、文档/可视化生成（产出物直接可用）。

### 6.2 功能增强建议（按 ROI）

| 优先级 | 能力 | 理由 |
|--------|------|------|
| P0 | 自动化引擎 | 用户明确要「进一步增强」；定时/周期性 agent 是生产力杠杆，且不依赖在线 API |
| P0 | 任务管理面板 | 多步任务可视化拆分与追踪，直接提升「可控性」体验 |
| P1 | 插件市场 + UI 真激活 | 复用已落地的 `plugin-host` 内核，把「零依赖内核」变成「用户可装可用」 |
| P1 | 浏览器自动化 | 网页信息抽取/填表闭环，与 fs 工具形成「线上+本地」双通道 |
| P1 | 文档生成（docx/pptx） | 对话产出直接落盘为可交付物，契合「给结论」诉求 |
| P2 | 可视化内联 | 数据/架构图随对话渲染，提升解释力 |
| P2 | 云端记忆同步 | 跨设备连续性，但涉及账号体系，投入大 |

## 8. 结论

当前 `DeepSeekAgent` 在**会话组织、工作空间、多模型、视觉输入、工具/MCP、技能、稳定性**维度已与 WorkBuddy 持平，是扎实的本地优先 agent 客户端。

**主要差距集中在三类**：
1. **交互友好型**（用户重点）：缺命令面板、统一通知、快捷键、设置聚合——这些是「用得爽」的关键，建议 P0 优先。
2. **自动化与任务管理**：缺定时/周期执行与任务可视化——这是「 agent 真正替我干活」的杠杆，建议 P0。
3. **生态与产出物**：缺插件市场、浏览器、文档/可视化生成——建议 P1/P2 分阶段补齐。

增强顺序建议 **P0 交互 + 自动化 → P1 插件/浏览器/文档 → P2 可视化/多模态/云端记忆**，可在不引入在线依赖的前提下显著提升智能体的可用性与生产力。
